# Harvest Feedback — code-derived design specification

This specification describes the **current source**, not a proposed redesign. Target rebuild: React + Vite + TypeScript + Tailwind v4. All lengths are CSS pixels. The source has many historical overrides; later applicable declarations and specificity determine the result. Detailed responsive rules and exact runtime copy are preserved in the appendices. Do not implement every legacy class as a new screen.

## Package and verification

`source/Harvest Feedback.html` is the entire application: HTML, inline CSS, vanilla JavaScript, SVG symbol definitions and a data-URI favicon. It has no external stylesheet, script, image or font dependency. No JSX/TSX project exists in this deliverable. All original icons remain embedded, not re-created or exported. Uploaded attachments live in the originating browser's IndexedDB and are **not** source assets; seed filenames do not refer to bundled images. `source/Harvest Color Palette.html` and `.json` are companion palette artifacts, preserved at the same relative level as the app. Historical reference designs, intermediate scripts and prior archives are not dependencies of the final design and are excluded.

Source files are copied byte-for-byte. SHA-256 values appear in `SOURCE_MANIFEST.json`. The app itself has not been edited for this handoff.

## 4. State behavior

- Initial sign-in has empty email; submitting invalid email gives “Enter a valid work email.” Code mismatch gives “Use 123456 to try this local demo.” There is no real email-send loading state.
- Form required-field errors combine “Please ” with missing instructions and focus the first missing control. Description count updates on input. Draft success/restore/unavailable states update the header text. Attachment selection uses blob preview; upload is actually a local IndexedDB write, not a network upload. Submit disables during that write; no spinner or percentage-progress design exists.
- Successful submission clears form, attachment and draft and shows toast. Storage failure either keeps session-only data or reports attachment failure. Exact messages are in Appendix C.
- Duplicate suggestion requires at least three significant words, ≥3 shared words, score ≥.4 and matching selected area; maximum three suggestions. Its helper still says a comment can be added, but the final dialog has no comment UI: document this mismatch rather than inventing an editor.
- Empty client/admin lists have separate messages. Zero pagination shows `0 reports`, `Page 1 of 1` with both controls disabled. Search/filter edits reset page1; out-of-range pages clamp.
- Request update records a local activity event and toasts. It is disabled while a request exists without a later Admin activity; closed disallows it. No email is sent.
- Report dialog attachments: none; sample filename without file; loading asynchronously without explicit spinner; image/video+download; unavailable file; storage error. No fabricated attachments.
- Recorder: unsupported inline error; sharing picker; recording elapsed timer; Stop; review+Attach/Discard; permission cancellation; recorder error; empty/oversize output; success toast. Capture request button is disabled while opening the picker.
- Errors/Traffic are populated local samples, no API loading/refresh skeleton. The issues list has four fixed rows filterable by project. Linked issue changes Make a report to View report.
- Theme/layout preferences persist in localStorage. Session email in sessionStorage can restore the session. No real authorization or cross-device data.

## 5. Theme and visual effects

Default HTML `data-theme="dark"`. Initialization forces dark on first `harvest-amber-v1` run; later reads `harvest-theme`. `theme()` writes the root attribute and persisted preference, updates authenticated sun/moon icon and accessible title to the opposite theme. Signed-out toggle is top right `#auth-theme`; authenticated toggle is top right `#theme-toggle`. Auth toggle invokes the same theme setter, although its own SVG is not changed by that function.

Semantic token table follows in Appendix A. Use CSS variable names in components; do not substitute Tailwind palette defaults. The pill dot literals are intentionally distinct from historical `--bug` / `--improvement` tokens still used elsewhere.

Glass: panels, rail, top bar, dialogs and auth card use 18px standard/WebKit backdrop blur. Dialog overlay uses `#03090eb5` and4px blur. Generic panel/dialog shadow `0 4px 22px rgba(0,0,0,.035), inset 0 1px 0 rgba(255,255,255,.15)`. Dark panels/auth override to `0 8px 28px rgba(0,0,0,.12), inset 0 1px 0 rgba(245,203,158,.055)`; light panels/auth `0 8px 30px rgba(118,88,57,.045), inset 0 1px 0 rgba(255,255,255,.85)`. Queue metric final overrides shadow to none, selected inset only. Toast still uses `--shadow`.

Dark body: `radial-gradient(ellipse 65% 50% at 88% 0%,rgba(198,111,45,.045),transparent 72%), radial-gradient(ellipse 48% 65% at 4% 90%,rgba(177,99,42,.022),transparent 75%), var(--bg)` with fixed background attachment.

Light body: `radial-gradient(ellipse 65% 50% at 92% 0%,rgba(204,130,63,.065),transparent 72%), radial-gradient(ellipse 50% 55% at 0% 100%,rgba(204,130,63,.03),transparent 75%), var(--bg)`. This final background shorthand resets prior background-attachment to its initial scroll value; do not assume it is fixed just because an earlier rule said so.

`--admin-haze`: dark rgba(198,111,45,.028), light rgba(196,123,59,.035). Used in grey panel gradients, signal cards, admin grid backgrounds. Traffic bars animate chart-grow scaleY from.04/opacity.2 to1/opacity.8 over700ms ease-out, transform-origin bottom; older unused usage bars specify900ms/stagger. `prefers-reduced-motion:reduce` removes chart animation. Drop borders and queue backgrounds transition150ms. Button hover brightness1.08 is the shared effect; no elaborate page transition.

## 8. React / TypeScript / Tailwind v4 rebuild notes

Preserve visuals and behavior, not the accumulated override architecture. Use typed enums for Priority and Severity, typed report/attachment records, reusable shared controls, explicit dialog state, and scoped semantic CSS tokens. Tailwind v4 arbitrary values or component CSS can preserve precise geometry and raw variable names. Do not rename active view states into new product features. Route names can be chosen in the target app; none are specified by this HTML. Do not add services, real auth, publishing, email or live Sentry/GA as part of a visual port without a separate integration decision.

Acceptance review should cover all screen inventory entries in both themes; 1440/1024/768/390px widths; list/grid size stability; internal scrolling/pagination; tag-column alignment with content-sized pills; pending/closed records; optional custom area; attachment preview and unavailable states; code/input error states; reduced motion; keyboard focus and dialog close. Use source CSS appendices to resolve differences. This package makes no claim that those browser checks have run.
